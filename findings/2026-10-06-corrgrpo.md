# Finding — CorrGRPO fixes multi-reward GRPO normalization bias (Oct 2026)

**Source:** AI Weekly alert summarizing a new arXiv paper (Wenbin Hu et al.), code released.
**Link:** https://aiweekly.co/alerts/corrgrpo-fixes-grpo-normalization-bias-in-multi-reward-rl
**Code:** https://github.com/HKUST-KnowComp/CorrGRPO
**Filed:** 2026-10-06

## What it reports (short summary)
- In vanilla GRPO, rollout rewards are centered and divided by the within-group standard deviation. When multiple rewards are combined (for example correctness plus a style score), the pooled standard deviation is built from pairwise covariances, so a large-scale reward can dominate normalization and suppress smaller-scale reward signals.
- CorrGRPO replaces those raw covariance terms in the denominator with Pearson correlation coefficients, leaving the centered total reward unchanged but changing how each reward component influences advantage magnitude.
- Reported results: on LeetCodeDataset code generation with Qwen2.5-Coder, CorrGRPO beats GRPO by roughly +2.09 to +4.21 Pass@1 across 0.5B–7B scales (7B: 47.28% → 51.49%).
- Also evaluated on tool calling and agent security; the alert notes a large tool-calling/security lift (Qwen2.5-7B joint accuracy on Agent Security Bench: 31.38% → 47.88%).
- Code is public at HKUST-KnowComp/CorrGRPO.

## Verified 2026-10-09 (paper + repo read)
- Paper: arXiv:2609.36820v1, "CorrGRPO: Correlation-Normalized GRPO for Multi-Reward Learning", Wenbin Hu et al., HKUST, submitted 29 Sep 2026. https://arxiv.org/abs/2609.36820v1
- Table 1 (LeetCodeDataset + HumanEval/MBPP/LCB v6, Pass@1): CorrGRPO beats GRPO on the four-benchmark average at every scale. Paper §4.1 reports average gains over GRPO of +2.09 (0.5B: 25.96→28.05), +0.80 (1.5B), +2.27 (3B), +4.21 (7B: 47.28→51.49). The alert's "+2.09 to +4.21" range omits the 0.80 low end.
- Table 3 (agent security): ASB Joint Accuracy Qwen2.5-7B GRPO 31.38% → CorrGRPO 47.88% — confirmed. Qwen2.5-3B: 14.88%→18.13%; Qwen3-8B: 57.38%→58.63%. Tool calling RLLA-4K all-exact Qwen2.5-7B: 63.38%→67.61%.
- Code: https://github.com/HKUST-KnowComp/CorrGRPO (public, created 2026-09-30). Built on **verl**, not TRL. Core change is `compute_grpo_covariance_coefficient_outcome_advantage` in `verl/trainer/ppo/core_algos.py`, registered as `grpo_covariance_coefficient` — a ~15-line denominator swap (covariance sum → sum of squared Pearson correlations, sqrt). Porting to TRL `GRPOTrainer` means writing a custom advantage computation; it is not a drop-in flag.
- A100 fit: experiments span 0.5B–8B, so model sizes fit the single A100 80GB. Training stack (verl + vLLM + FSDP) is heavier than TRL for a first lab.
